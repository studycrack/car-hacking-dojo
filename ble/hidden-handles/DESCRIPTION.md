Every enumeration you have done asked the peripheral to describe itself, and
took the answer at face value.

That answer is generated by firmware. A Read By Type response is a list the
device chose to send, and the device is free to leave things off it -- an
engineering characteristic, a debug channel, whatever the manufacturer would
rather the phone app not render a button for.

Leaving an attribute out of a discovery response does not remove it from the
attribute table. **The handle still works.** Nothing in ATT consults the
discovery list when a Read Request arrives; it looks up a handle and serves it.

So enumerate the way the protocol actually allows, rather than the way the
device suggests: walk the handles. `0x0001` upward, one at a time, reading each
and noting what comes back. `Invalid handle` means nothing is there.
Anything else means something is.

Handles are small integers and there are not many of them. Write the loop.

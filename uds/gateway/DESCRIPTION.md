# gateway routing table을 읽고 다른 버스에 닿기 (Gateway)

이 단계의 목표는 다음과 같습니다:
*  실제 차량에는 버스가 여러 개 있고, 일부러 서로 떨어뜨려 놓습니다. 그 사이에 **중앙 gateway**가 있어서 건너가야 할 메시지만 옮깁니다.
*  OBD-II 커넥터는 gateway의 진단 쪽에 있습니다. 파워트레인 버스에 있지 않습니다.
*  이번 워크스페이스에는 인터페이스가 두 개입니다.

```
ls -l /run/vcan/
```

*  커넥터가 닿는 것은 `vcan0`이고, `vcan1`을 들으려 하면 그 버스에 있지 않다는 답을 받습니다.
*  그러니 버스가 아니라 **버스를 이어 주는 것**을 공격해야 합니다.
*  gateway가 파워트레인 쪽으로 넘겨주는 ID를 알아내, 그 경로로 이모빌라이저의 routine `0xC001`을 실행해야 합니다.

과제:
*  진단 버스에서 gateway를 찾으세요. 다른 컨트롤러처럼 응답하므로 열거 방법은 앞에서 익힌 그대로입니다.
*  gateway의 식별 기록을 훑어 routing table을 읽으세요.
*  넘겨주는 ID 목록에서 진단 주소로 보이지 않는 항목을 고르세요.
*  그 ID로 이모빌라이저에 UDS request를 보내 routine을 실행하세요.

```
31 01 C0 01
```

힌트:
*  목록을 꼼꼼히 보세요. 세 개는 평범한 진단 주소이고, 하나는 훑어볼 생각조차 하지 않았을 범위에 있습니다.
*  routing table을 의심하지 마세요. 개발 중에 한 번 작성되어 연식마다 복사되고, 거의 감사되지 않습니다.
*  응답 주소는 요청 주소보다 여덟 개 위라는 규칙을 그쪽에서도 적용하세요.
*  인증을 찾지 마세요. 이모빌라이저는 닿기만 하면 `0xC001`을 그대로 실행합니다.

routine이 실행되면 응답에 플래그가 담겨 옵니다!

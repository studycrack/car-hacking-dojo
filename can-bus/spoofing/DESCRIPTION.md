# signal을 역공학해서 계기판 속이기

이 단계의 목표는 다음과 같습니다:
*  문을 열 때는 메시지 layout을 알려드렸습니다. 현장에서는 아무도 알려주지 않습니다.
*  ID와 바이트 위치는 제조사·차종·연식마다 다릅니다. 공개되지도 않습니다.
*  그래서 **볼 수 있는 것**과 **캡처할 수 있는 것**을 맞춰 보며 알아냅니다.

과제:
*  계기판 화면을 띄우세요.

        /challenge/dashboard

*  바늘을 따라 움직이는 payload 바이트를 찾으세요.
*  값이 어떻게 인코딩되어 있는지 알아내세요. 단순한 km/h가 아닙니다.
*  계기판이 **정확히 133 km/h**를 가리키게 만드세요.

힌트:
*  `candump`는 너무 빨리 흘러갑니다. `cansniffer -c vcan0`을 쓰세요.
*  ID마다 한 줄을 유지하고 바뀐 바이트를 색으로 표시합니다. `q`로 나옵니다.
*  바이트 쌍과 화면 값을 비교하면 scale을 역산할 수 있습니다.
*  바늘을 따라가는 ID는 하나가 아닙니다.
*  하나는 계기판이 **듣는** 값입니다. 다른 하나는 계기판이 **알리는** 값입니다.
*  공격할 가치가 있는 것은 앞의 것뿐입니다.
*  **화면으로는 확인할 수 없습니다.** 화면은 상태 frame이 말하는 대로 그립니다.
*  상태 frame 쪽에 주입하면 계기판은 아무것도 믿지 않았는데 화면에는 133이 뜹니다.
*  구분하는 방법이 있습니다. 상태 frame에는 속도 옆에 엔진 RPM이 함께 실립니다.
*  휠 속도 센서는 엔진 상태를 알 리가 없습니다.
*  진짜 센서가 초당 다섯 번 사실을 보냅니다. 계기판은 마지막에 도착한 것을 믿습니다.
*  **3초 동안** 실제 frame을 밀어낼 만큼 계속 보내야 합니다.
*  셸에서 `cansend`를 반복하면 속도를 못 맞춥니다. 파이썬으로 직접 붙으세요.

        import sys
        sys.path.insert(0, "/challenge")
        import vcan

        bus = vcan.Bus("vcan0")
        bus.send(0x123, bytes([0x11, 0x22]))

계기판이 133을 믿기 시작하면 플래그가 버스로 나옵니다!
